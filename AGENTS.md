# Інтеграція Hustle

Користувач авторизував підключення нового дизайну до цього репозиторію. Для `cms_obgortka` дозволено використовувати наявні API та робити необхідні інтеграційні зміни. Батьківська вимога «суто візуальний прототип» продовжує стосуватися окремих файлів прототипу поза цим репозиторієм.

- Новий вебінтерфейс — `app/static/hustle/`, URL `/hustle/`.
- Зберігай старий інтерфейс і чинні API. Не видаляй файли чи наявні напрацювання.
- Використовуй справжні відповіді API; не підмінюй помилки демонстраційними даними чи удаваним успіхом.
- Зберігай вершковий light-first дизайн, доступність і лаконічні змістовні підписи.
- Не зберігай паролі, токени Moodle або OAuth у localStorage/sessionStorage.

## Навігація інтегрованого простору

- Зберігай постійний доступ до додавання Moodle-курсів після реєстрації.
- Множинний вибір має зберігатися при пошуку; повторюються тільки невдалі імпорти.
- Глобальне меню, вкладки курсу та зміст тем — три різні рівні. Не підмінюй один іншим.
- Зберігай пошук, фільтри й чернетки при переходах; повідомлення про оновлення не повинні перезаписувати поточний екран.
- Уточнення структури матеріалів не замінює конспекти, особисті нотатки або історію практики.
- Тестуй інтеграцію в окремій БД; не вмикай MOODLE_MOCK_MODE для основного сервера.

## Навігація навчального простору

- Основні розділи: «Мої курси» та «Дедлайни». Налаштування залишаються внизу. Матеріали та практика доступні всередині конкретного курсу.
- Початкова сторінка курсу показує теми. Конспект відкривається з теми; картки й самоперевірка доступні поруч із читанням.
- Дедлайни групуються за датою й фільтруються за курсом. Минула дата не означає, що користувач не здав роботу: не показуй статус прострочення без даних про здачу.
- На головній та в курсі показуй тільки реальні кількості й завдання. Не вигадуй відсотків прогресу, streaks або персональних рекомендацій.
- Зміна оформлення не повинна порушувати старі посилання на конспекти, нотатки, файли, практику та інструменти курсу.
