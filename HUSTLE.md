# Hustle: перше підключення дизайну

Новий інтерфейс: http://127.0.0.1:8000/hustle/
Старий інтерфейс лишається за `/` та університетськими URL.
Візуальний прототип у батьківській папці не змінено.

## Запуск

```sh
.venv/bin/python run.py
```

Нові файли інтерфейсу — `app/static/hustle/`. Вони використовують наявні API на тому самому origin та HttpOnly cookies. Демодані, прапорець локальної «реєстрації» і вигаданий прогрес сюди не підключені.

## Підключено

- Лендінг Hustle, Google OAuth і наявний гостьовий workspace.
- Список курсів із `/api/workspace/courses`.
- Створення курсу з тексту або файлу через наявні upload/create-text API.
- Перегляд тем, текстових пояснень та флешкарток із course bundle.
- Профіль і стан Moodle із `/api/auth/status`.
- Підключення Moodle токеном, список курсів і серверна синхронізація вибраного курсу.
- Вихід через наявний logout API.

## Межі цього етапу

Вхід за email/паролем у backend відсутній. Google потребує налаштованих GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET та GOOGLE_REDIRECT_URI. Після входу, розпочатого з Hustle, callback повертає в `/hustle/app.html`; попередній сценарій зберігає повернення на `/`.

Без GEMINI_API_KEY сервер використовує свій генератор-заглушку. Персональний план, облік прогресу, редактор нотаток, повна практика, повний рендеринг Markdown/Mermaid і керування генерацією поки не перенесені. Пояснення підтримують базове форматування Markdown; вхідний HTML екранується.

Гостьовий простір прив'язаний до браузерної cookie; це не постійний обліковий запис. Автоматичний перенос гостьових курсів між способами входу цим UI не реалізовано.

## Другий етап: навчальні розділи

- Окремі бібліотеки практики й матеріалів у бічному меню.
- Вкладки курсу: конспект, практика, матеріали, підготовка до іспиту.
- Нотатки з PATCH `/api/workspace/mixes/{mix_id}/notes`; незбережені чернетки залишаються в пам'яті при навігації між вкладками, помилки не стирають введений текст.
- Послідовне повторення флешкарток із відповіді API. Статистика повторення карток не записується: відповідного API немає.
- Квізи з перевіркою та POST `/api/workspace/mixes/{mix_id}/quiz-attempt`. Наступне питання відкривається після успішного запису; при помилці можна повторити запит.
- Формування/оновлення ExamMix через POST `/api/workspace/courses/{course_id}/exam-mix`, збережений сервером конспект та список слабких тем. Пробний іспит показує локальний результат; окремого endpoint для його спроб немає.
- Матеріали з course bundle: пошук, посилання на джерела, виключення restricted_exam. Посилання обмежені HTTP(S), вхідний текст екранується.
- При імпорті можна обрати генерацію карток і самоперевірки.
- Розширено базове відображення Markdown: заголовки, списки, цитати, код. Mermaid поки не малюється.

Попередній перелік меж першого етапу вище описує стан до цього розширення. Персональний розклад/план, повне редагування інструментів курсу та фонові сповіщення ще не підключені. У поточних routers не знайдено API персонального навчального плану.

Перевірка другого етапу: браузерні сценарії нотаток, карток, квізів, ExamMix, імпорту, помилок і повторних спроб; ширини 320–1440 px. Цільові тести API нотаток/телеметрії/ExamMix та матеріалів: 9 passed. Реальні Google/Moodle і платний Gemini не використовувалися.

## Третій етап: підключення через розширення

Основний екран `/hustle/connect.html`: завантаження ZIP, короткі інструкції встановлення, автоматичне визначення розширення, вибір Moodle, підтвердження доступу до сесії та вибір курсів. Токен лишається додатковим способом у згорнутому блоці.

Архів формується тільки з явного списку публічних файлів розширення. Не містить `.env`, БД, OAuth-ключів або іншого серверного коду. Встановлення ZIP Chrome вимагає підтвердити вручну. Упаковану папку перевірено в окремому тестовому Chromium із реальним завантаженням розширення та визначенням сайтом. Жива університетська сесія не використовувалася; pairing/sync transport перевірено з mock Chrome API та тестовими відповідями.

Розширення передає MoodleSession обраному серверу після явного підключення. Автоматичне поновлення обмежено погодженою парою LMS/Hustle. Перед синхронізацією pairing завершується до визначення поточного workspace, щоб не використати застарілу гостьову ідентичність. Неактивна сесія відкриває Moodle для повторного входу; помилка сервера не маскується успішним підключенням.

Для публічного розгортання: `HUSTLE_PUBLIC_ORIGIN=https://...`; після публікації в магазині — `HUSTLE_EXTENSION_STORE_URL=https://chromewebstore.google.com/detail/...`. Посилання на магазин автоматично замінює ZIP-кнопку. Публікацію не виконували. Автоматичні оновлення можливі через магазин; розпаковану тестову версію оновлюють вручну.

Перевірено 320, 390, 768, 1440 px без горизонтального переповнення. Скриншоти — `/Users/yurleomel/Desktop/PetProjects/hassle/output/playwright/hustle-v2-*.png`.

Рендеринг Markdown очищає HTML через DOMPurify, Mermaid працює в strict mode без HTML labels. Бібліотеки зібрано локально; браузер не залежить від CDN. За потреби повторної збірки: `npm install --prefix tools/hustle-ui`, потім `node tools/hustle-ui/build.cjs`.

Реальні можливості залежать від дозволів Moodle і активної сесії. Gemini потребує серверного ключа; без нього залишається наявний детермінований генератор репозиторію. Транскрипт доступний лише коли відеопровайдер має субтитри; це не розпізнавання довільного аудіо. Пробний іспит має локальний результат, оскільки endpoint збереження його спроб у репозиторії відсутній. Персональний календар навчального плану також не має backend API. Адміністративні діагностика, webhooks та очищення сховища залишаються в попередньому інтерфейсі/API.

Фінальна перевірка завантажень: REST `contents` та HTML resource-посилання підтримуються; вкладення вибирається за filename. ZIP і перевірку доступу перевірено API-тестами з ізольованими файлами. Браузерну доставку ZIP перевірено тестовою відповіддю; реальні університетські файли не викачувалися.

Фінальний перегляд конспекту: службовий текст детермінованого генератора та повтори його підсумків приховано лише на рівні відображення; збережені джерела не змінюються. Перевірено в браузері відновлення чернетки після помилки збереження, безпечний Markdown і видимі підписи Mermaid.

## Навігація й навчальний простір — 17 листопада 2026

Головне меню містить «Мої курси» та «Дедлайни», налаштування залишаються внизу. Загальні бібліотеки матеріалів і практики більше не показуються в меню; старі адреси цих двох сторінок ведуть до курсів. Старі посилання на конкретні матеріали, конспекти, практику й інструменти збережено.

Курс відкривається з тем. Конспект належить темі; картки та самоперевірка доступні без виходу з читання. Підготовка до іспиту розміщена всередині практики, оцінки — поруч із дедлайнами. Перемикач курсу зберігає поточний розділ, а при виході з конкретної теми відкриває огляд іншого курсу. «Продовжити» веде до теми, відкритої в поточній сесії вкладки, без вигаданого прогресу.

Головна використовує оформлення зошитів та блок найближчих завдань. Матеріали згортаються за темами; пошук розгортає збіги. Дедлайни згруповані за датою у часовому поясі Europe/Kyiv, мають фільтри періоду та курсу, деталі й посилання на підключений Moodle. Показуються завдання лише доданих курсів; сторінка курсу додатково перевіряє course_id навіть якщо API повертає зайві записи. Минулі строки не позначаються як нездані роботи. Для курсів із власних файлів Moodle-дедлайни не показуються.

Джерела рішень: [Linear — calmer interface](https://linear.app/now/behind-the-latest-design-refresh), [Atlassian — navigation best practices](https://support.atlassian.com/navigation/docs/navigation-best-practices/), [NN/g — progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/).

Перевірка: 8 Node-тестів групування дат, межі дня за Києвом, фільтрації та ізоляції курсів (`node --test tests/hustle_navigation.test.cjs`). У браузері перевірено 5 екранів на ширинах 320, 390, 768, 1024, 1440 px, без горизонтального переповнення. Проклікано тему → картки/квіз, запис спроби, чернетки й запис нотаток, пошук і згортання матеріалів, перемикач курсів, підготовку до іспиту, оцінки, фільтри дедлайнів і повернення назад, діалоги імпорту та мобільне меню. Виправлено збереження початкового переносу рядка нотаток після повторного відображення textarea.

Додатково перевірено порожню бібліотеку, порожні дедлайни, курс із власних матеріалів, пошук без результатів після повернення на головну, повтор завантаження після HTTP 500 і перенаправлення старих глобальних адрес. Нові сценарії не показали необроблених JS-помилок. QA працював на окремому сервері 8002 та тестовій БД; дати завдань для сценаріїв «сьогодні/завтра/минулі» підмінялися лише у тестовому браузері. Основний сайт не використовує ці фікстури. Реальні університетські дані, Google-вхід і платний Gemini в цій перевірці не використовувалися.

## Повторні версії тем

Старі генерації могли зберегти різні `mix_id` з хешем вмісту для одного `owner_id + course_id + topic_index`. Курс і лічильники тепер вибирають одну актуальну генерацію за версією, часом оновлення та ID. Однакові назви різних розділів не об’єднуються. Історичні рядки, нотатки та спроби практики залишаються в БД.

Запис генерації атомарно використовує чинний ID теми, зберігає нотатки й не створює ще один рядок при зміні хешу або паралельному імпорті. Посилання на нотатки та оновлення старої генерації працюють з актуальною темою; явно очищені нотатки не відновлюються зі старої версії. Регресійні сценарії — `tests/test_topic_identity.py`.

## Дашборд «Мій план», бренд і паперові деталі

Початковий маршрут навчального простору — `#dashboard`; «Мої курси» й «Дедлайни» залишаються окремими розділами. Композиція дашборду відтворює початковий візуальний прототип: чотири дні, велика вершково-жовта картка заняття, чекліст і два допоміжні блоки під ним. Повний каталог не дублюється на дашборді.

`dashboard-plan.js` отримує справжній bundle вибраного курсу. Остання відкрита тема використовується для продовження, курс можна змінити в картці. У завданнях є лише доступні інструменти теми: конспект, картки та самоперевірка. Практика відкриває наявні навчальні діалоги; читання — чинний маршрут теми. Вигаданих тривалостей немає.

Чекліст користувач позначає вручну. Вибір і позначки зберігаються в `sessionStorage` вкладки, окремо для власника, дня, курсу й теми. Відсоток обчислюється з цих позначок, а не представляє оцінку Moodle чи автоматично визначений прогрес. Серверного планувальника або синхронізації чекліста між пристроями на цьому етапі немає. Дати відображаються за Europe/Kyiv; вибір дня також змінює нижню межу списку найближчих дедлайнів.

Використано наявні `/api/workspace/courses`, `/api/workspace/courses/{id}`, `/api/assignments` і `/api/workspace/events`. Дедлайни й події обмежено доданими курсами. Порожні результати й помилки мають власні стани та повтор завантаження. Знайдено старий дашборд колег у `app/templates/index.html` та `app/static/js/app.js` із курсами, завданнями, оцінками й подіями. AI Coach і планування слотів описані в README, але реалізації відповідного планувальника в перевірених гілках `main`/`smth` немає.

Новий SVG wordmark використовує складений аркуш як літеру h; оновлено favicon і чотири сторінки нового інтерфейсу. ## Структура та орієнтація — 18 листопада 2026

Актуальна головна — «Сьогодні» (`focused-home.js`). Один пріоритет із прямим переходом до завдання та матеріалів його теми, коротка черга інших термінових справ, розкривний список наступних днів і повернення до останньої навчальної теми. Одна робота не повторюється в різних віджетах. Календарні обгортки назв на кшталт «Строк … спливає» прибираються лише з відображення. Джерельні назви збережено.

`workspace-frame.js/css` задає спільний відкритий каркас: глобальне меню, доступні курси або зміст поточного курсу збоку, шлях до сторінки зверху, спокійні підкреслені вкладки. Налаштування залишаються внизу. Великі обкладинки курсу та множинні рамки більше не займають основну площу. Текст, списки матеріалів і практика мають власні рівні, а поточна тема виділена в змісті. На вузьких екранах зміст переходить у наявне бічне меню.

Карта зберігає оригінальну ієрархію Moodle: частина → тема → лекція, читання, семінар, самотест. `course_map` — додаткове подання bundle, яке не переписує історію TopicMix. Старі `section-N` посилання підтримуються поряд зі стабільними Moodle section ID. Нормалізатор читає машинне `module`, а не перекладене `modname`, зберігає parent/section metadata, стан завершення, порядок і текстові роздільники. Для старих знімків допустимі лише однозначні зв’язки; повторні назви Lecture/Lab не групуються навмання.

Виправлено підбір матеріалів: внутрішній section index 11 більше не зіставляється з навчальною Topic 11, якщо назва означає Topic 3. Несумісні блоки, технічні підсумки-заглушки й шаблонні квізи не показуються як навчальний матеріал. Читач зберігає абзаци, заголовки й списки; джерела, практика та нотатки розділені. Справжні схеми й візуальні пояснення збережено. Оригінальні файли, тестові сторінки й завдання відкриваються за їхніми Moodle URL; приватні питання тестів не скрапляться.

`/api/assignments/submission-status` запитує фактичний статус роботи в Moodle з обмеженням паралельності й кешем, ізольованим за сайтом, користувачем і сесією. Після завершення строку без підтвердження онлайн-здачі відображається невідомий статус, а не вигадане прострочення. Дашборд обмежує очікування цього уточнення, щоб недоступна служба університету не блокувала весь екран. Часові межі — Europe/Kyiv.

### Межі навчальної логіки та стан Git

Перевірено віддалені `main` і `smth` через fetch. `origin/main` на момент перевірки — `145f584af6e6ded602a4663fc06fbc70fa5af41c`. Новий patch містить звернення до відсутнього в його дереві `app.services.academic_cache`; автоматичний merge не виконувався. Локальні зміни, попередні дизайни, основна БД та історичні записи збережені; резервні копії — в ігнорованій `backups/`.

У репозиторії є TopicMix, картки, квізи, спроби та ExamMix. Реалізації персонального AI Coach/адаптивного планувальника в перевірених гілках немає. У поточній локальній конфігурації Gemini не налаштований, тому новий інтерфейс не обіцяє готове AI-навчання й не видає технічний fallback за пояснення теми. Поточне покращення — достовірна структура, орієнтація, джерела та черга справ; це не автоматичний педагогічний план.

## Дашборд із найближчим завданням та огляди курсів — 18.11.2026

`dashboard-today.js/css` задає новий основний дашборд у збереженому вершковому оформленні: найближче завдання, продовження навчання поруч, інші справи нижче без повторення головної. Показуються лише завдання імпортованих курсів; здані роботи не потрапляють у чергу. Підтверджені нездані роботи видно окремим статусом, а невідомі статуси минулих робіт згорнуті. Початковий дашборд лишився у `student-home.js`; копія файлів до зміни — `backups/dashboard-before-20261118-012031/`.

`course-today.js/css` додає вкладку «Огляд» для кожного курсу. Повна структура доступна у «Темах» (`#course/:id/topics`). Огляд показує завдання саме цього курсу та прямі дії: відкрити завдання, матеріали відповідної теми, квіз Moodle або наявні картки/самоперевірку. Для подій квізів адреса береться з модуля Moodle, а не будується як адреса здачі завдання. Джерельні квізи відкриваються на сторінці Moodle; спроби автоматично не запускаються.

Навчальна тема прив’язується до секції найближчого завдання. Якщо відповідної секції немає, використовується остання відкрита тема цього курсу, а далі — перша навчальна тема в його ієрархії. Контекст читання зберігається в sessionStorage окремо для акаунта та курсу; це навігація, а не модель засвоєння. Для власних матеріалів залишено чинний reader і TopicMix. API, основна БД та збережена порівняльна версія не змінювалися.

Перевірка: 24 Node-тести пріоритетів, статусів, дедуплікації, вибору тем, умов доступності квізів і правильних адрес. Дашборд, огляд і карта курсу перевірені на 320, 390, 768, 1440 та 2560 px без горизонтального переповнення. Окремо проклікано тему → квіз, огляд → матеріали → карта курсу, помилку дедлайнів → повтор, порожній простір і власний курс. QA працювала з окремою БД та контрольованими відповідями тільки в тестовому браузері.

Додатково перевірено окремий контекст читання для різних курсів і повернення через перемикач. Контрольні суми всіх 160 файлів збереженого порівняльного варіанта збігаються. Основний сервер віддає нові компоненти з HTTP 200.
